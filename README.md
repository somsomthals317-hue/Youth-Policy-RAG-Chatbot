# 🚀 남양주시 청년정책 챗봇 '두물청'

> 정책 데이터 전처리부터 RAG 검색, 자격 확인, 맞춤 추천까지 구현한 AI 챗봇 프로토타입

---

## 📌 1. 프로젝트 개요 (Overview)

- **개발 기간:** 2026.08.10 ~ 2026.08.26
- **프로젝트 유형:** 개인 프로젝트
- **개발 목적:** 남양주시 청년정책의 정보 접근성을 개선하고, 사용자 조건에 맞는 정책 안내 및 추천 기능 제공
- **주요 결과:**
  - 남양주시 청년정책 32개를 대상으로 정책 데이터 구축
  - 정책 알아보기, 맞춤 추천받기, 자격 확인하기 3가지 기능 구현
  - 사용자 의도에 따른 Intent Routing 및 Multi-Turn 대화 처리
  - FastAPI 기반 서비스 구현 및 Render 배포

남양주시 청년정책은 사용자가 개별적으로 검색해야 하는 번거로움이 있고, 정책마다 지원 자격이 달라 본인에게 적합한 정책을 판단하기 어렵다는 문제가 있습니다.

이를 해결하기 위해 정책 정보를 검색하는 RAG 기능과 사용자 조건을 확인하는 자격 판별 로직을 분리하고, 하나의 대화형 인터페이스에서 정책 안내부터 맞춤 추천까지 제공하도록 설계했습니다.

---

## 🛠️ 2. 기술 스택 (Tech Stack)

- **Language:** Python
- **LLM:** LLM API
- **RAG & Retrieval:** ChromaDB, RAG
- **Backend:** FastAPI
- **Deployment:** Render
- **Architecture:** Intent Routing, Query Rewriting, State Management

---

## 🏗️ 3. 시스템 아키텍처 (Architecture)

### 전체 서비스 흐름

**정책 데이터 전처리 → 자격 요건 구조화 → Intent Routing → 기능별 처리 → 최종 응답 생성**

### ① 정책 데이터 구축 및 관리

- 남양주시 청년정책 32개를 대상으로 정책 데이터 구축
- 정책 원문은 RAG 검색용, 나이·지역 등 자격 요건은 JSON으로 구조화하여 관리
- 검색과 자격 판별 목적에 따라 정책 원문과 정형 데이터를 분리하여 활용

### ② Intent Routing 기반 기능 분기

사용자의 질문 의도를 분석하여 3가지 기능으로 분기하도록 설계했습니다.

- **EXPLAIN:** RAG 기반 정책 검색 및 설명
- **ELIGIBILITY:** 사용자 프로필과 정책 자격 요건 비교
- **RECOMMEND:** 사용자 조건에 따른 정책 필터링 및 추천

### ③ 대화 맥락 및 복합 질의 처리

- **Query Rewriting:** 검색에 적합하도록 사용자 질문을 재구성하여 검색 정확도 개선 시도
- **State Management:** 사용자 정보와 이전 대화 맥락 유지
- **Multi-Turn:** 이전 대화에서 수집한 정보를 후속 질문에 활용
- **Multi-Query:** 하나의 질문에 여러 요청이 포함된 경우 독립적인 처리 흐름으로 분리

## ✨ 4. 주요 기능 및 본인 역할 (Key Features & Contributions)

### ① RAG 기반 정책 검색 및 설명

- 정책 원문을 검색 대상으로 구성하고 ChromaDB를 활용한 검색 파이프라인 구축
- 검색된 정책 정보를 LLM에 전달하여 사용자 질문에 대한 답변 생성
- Query Rewriting을 적용하여 사용자 질문을 검색에 적합한 형태로 보완

### ② 규칙 기반 자격 판별 및 맞춤 추천

- 정책별 자격 요건을 JSON 형태로 구조화
- 사용자 프로필과 정책 조건을 비교하는 규칙 기반 판별 로직 구현
- 규칙 기반 판단에 LLM을 결합하여 정책 자격 확인 및 맞춤 추천 기능 제공

### ③ Intent Routing 및 Multi-Turn 대화 관리

- 사용자 의도에 따라 정책 설명, 자격 확인, 맞춤 추천 기능으로 분기
- State Management를 통해 사용자 프로필과 대화 맥락 유지
- 복합 질문을 독립적으로 처리하는 Multi-Query 로직 구현

### ④ 사용자 인터페이스 및 서비스 배포

- 정보 부족 시 정책·관심 분야·사용자 프로필 선택형 UI 카드 제공
- 선택형 입력을 통해 추가 정보를 수집하고 후속 응답에 반영
- FastAPI 기반 서비스 구현 및 Render 배포

## 💡 5. 배운 점 (Troubleshooting)

### ① 정책 검색과 자격 판별의 역할 분리

정책 정보를 검색하는 과정과 사용자의 지원 자격을 판단하는 과정은 서로 다른 데이터 처리 방식이 필요하다는 점을 고려했습니다.

이에 따라 정책 원문은 RAG 검색용으로, 자격 요건은 JSON 형태로 분리하여 관리했습니다. 이를 통해 검색 기반 응답과 구조화된 조건 비교를 기능별로 구분하는 설계 경험을 쌓았습니다.

### ② Multi-Turn 환경에서의 사용자 정보 관리

사용자가 여러 차례 질문하면서 관심 분야나 자격 정보를 추가로 제공하는 경우, 이전에 수집한 정보를 유지하는 것이 중요했습니다.

State Management를 적용하여 사용자 프로필과 대화 맥락을 관리하고, 후속 질문에서도 기존 정보를 활용하도록 구현했습니다.

### ③ 기능별 처리 흐름 설계

정책 설명, 자격 확인, 맞춤 추천은 필요한 데이터와 처리 방식이 달랐습니다.

Intent Routing을 통해 사용자 요청을 기능별로 분리하고, 복합 질문은 Multi-Query 방식으로 처리하여 하나의 챗봇에서 여러 기능을 제공하는 구조를 구현했습니다.
